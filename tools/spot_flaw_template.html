    Dependency.Guard: a Mind that checks before it trusts
    
    
    For teams whose coding agents add and upgrade packages, and must not ship a known-vulnerable version. It runs inside Minds by Animoca Brands and buys its intelligence from Telegraph.
    
  
    

  
    
    
      
      
    1. [1]Buy one answerOne SECURITY_REVIEW answer per package from Telegraph's ranked route, through Anjoman. Never three providers by default.
      2. 
      
    2. [2]Check it for freeVerified Ask compares the verdict with OSV for that exact version, confirms every cited advisory exists and applies, and that the version was ever published.
      3. 
      
    3. [3]DecidePASS, BLOCK or FLAG, with the advisories, every receipt and the cost. One other provider is asked only when the check proves the answer wrong. Approved versions are re-checked daily.
      4. 
    
    
    
    
      
    Trusting the answer
    On 26 packages: 3 vulnerable versions passed, and 2 packages that don't exist were called "Secure".
    
      
    With the check
    Nothing unsafe was approved: 24 decided correctly, 2 sent to a person.
    
      
    Code review
    23 subtle functions: Telegraph's route 13, its best miner 11; the Mind 23, overruling all 10 wrong answers.
    
      
    Honest result
    The Mind on its own matched these scores by querying OSV directly. For known package vulnerabilities a free lookup is the bar; the value is that wrong paid answers never became decisions.
