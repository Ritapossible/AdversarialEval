# Seed merge `cpu-v3-merged`: SECURITY_REVIEW (audit item U8)

Date: 2026-11-11 · tool `tools/merge_seeds.py` · inputs: `cpu-v3-seed7` and `cpu-v3-seed13`
(same frozen 264 training pairs, same config, seeds differ). Validation: the same 87 frozen
pairs (`runs/frozen/val-87.jsonl`). Scoring: `eval/score.py` (PyTorch float path).

## Method

For each of the 88 LoRA modules, the merged update is the average (or sum) of the seeds'
effective updates `(alpha/r)·B·A`, refactored by SVD. Two rank-8 updates sum to rank ≤ 16,
so the rank-16 merge is **exact** (max error 5e-10; 100% of the energy kept). The reward
head is the average of the two heads. The merged package exports and passes the node's
Stage 1 check (`scripts/export.sh cpu-v3-merged-mean`: rank 16, 178 tensors,
13.5 MB, class judgment). It is **not registered**.

## Reading

- **Weight merging hurts.** Both merges score below either seed, and the loss falls on the
  generated minimal pairs.
- **Why:** the two seeds found unrelated solutions.
  - The reward heads have cosine similarity 0.01.
  - The LoRA updates for the same module have cosine similarity about 0 (−0.002 on layer 10 Wqkv).
  - Weight averaging ("model soups") only works when runs share an initialisation and
    sit in one loss basin. The kit uses one seed for both the LoRA/head init and the
    data order, and has no option to start from a given init. Getting a shared-init soup
    would mean modifying the vendored kit, which hard rule 4 forbids.
- **The score ensemble shows the variance is real and averaging it helps (+2.3 points over
  the mean of the seeds).** But the node runs one LoRA and one linear head per package, so
  the ensemble can't be submitted.

## Decision

Close U8 as a negative result. Don't submit a merged package. The 2-seed protocol stays
for *measurement*; for *submission*, pick a seed by a rule fixed in advance on independent
data (the U1 test split), not on this validation set. `tools/merge_seeds.py` stays: it's
tested, node-valid, and becomes useful if the kit gains an init option (worth raising with
the patches in `docs/upstream/`).
