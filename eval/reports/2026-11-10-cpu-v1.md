## Reading

- **On 39 held-out second-voice pairs the adapter scores 76.9%**, up from 61.5% for cpu-v0 with the same data. The changes: twice the learning rate and up to 6 epochs. Validation accuracy by epoch was 46, 59, 69, **77**, 82, 79%. Early stopping on validation loss kept epoch 3.
- **It's starting to overfit.** Training accuracy is 97.9% and training loss reached 0.04 by epoch 5, so more epochs won't help without more data.
- **It isn't measuring length.** When the rejected answer is padded to 1.5× length, 100% of the correct calls stay correct.
- **It's still weakest on the inversion families.** When the right verdict is *Secure* it scores 55%; false alarms (F6) and overconfident Secure (F5) are 60% each. The next data batch goes there.
- **Caveats before anyone compares this with the 70% floor or the incumbent's 71.43%:**
  1. Validation loss on these same 39 pairs chose the epoch, so 76.9% is mildly optimistic. With n = 39 the 95% interval is roughly ±13 points.
  2. The node's hidden test draws pool rows from many contributors. Our validation set is a single second voice, so the two numbers aren't directly comparable.
  3. These are PyTorch float scores. The node scores with the WASM engine; the confirmation step requires bit-exact executor output, but rankings should agree.
- **Next:** add a separate **test split** that no training decision ever looks at. Add more F5/F6 and Secure-verdict data. Then run 3 seeds to measure variance before any registration.
