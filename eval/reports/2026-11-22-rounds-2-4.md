## Findings

**1. The ranking improved in round 4, and the default route improved with it.**
- τ went from about zero (+0.02, −0.18) to **+0.29**. A positive τ means higher-ranked miners tend
  to be more accurate. With 32 miners and most at 0/36 the estimate is noisy, but this is the first
  round where the direction is right.
- The route follows rank 1 every round, so route accuracy is rank 1's accuracy: 5/36, 1/36, then
  17/36 once a better miner reached rank 1.
- **The new rank 1 is a rebuilt miner.** "salence" has the same miner id (`905227`) as
  "evidence-security-review", which scored 0/36 in rounds 2 and 3 (no delivered verdicts).

**2. The default route now answers only the "something is wrong" half.**
- salence (and so the route) flagged every affected package (12/12 plus 8/8 restated probes) and
  5 of 6 vulnerable code snippets.
- On all 12 clean package versions and on fixed code it returned `verdict: null` with count 0:
  no usable verdict, so "no answer" under the rule. It never says "Secure".
- For a buyer this is a half answer: an alert when there is a known flaw, silence otherwise. Its
  17/36 is the same as "always Insecure" minus the false alarms.

## Changes made while scoring

- **Rail on failed calls.** `bench/run.mjs` didn't record the payment rail on calls that failed in
  the client, so the scorer counted those under the x402 rule (charged). The scorer now fills the
  rail from the round's other calls, the runner records it, and `tests/test_bench.py` covers it.
  Effect: $0.01 on four miner-rounds in the "on-chain" column; no published headline changes.

## Limits

- Testnet, one payer wallet, 46 cases per round (36 answerable). Intervals are wide; read
  overlapping ones as ties.
- Code truth is by construction; package truth is OSV at build time.
- The market changed between rounds (21 new miners in round 3, a rebuilt rank 1 in round 4), so
  "stability" is only measured on the 13 miners present in all three rounds.
- One $0.01 charge in round 4 is unmatched (see above).
