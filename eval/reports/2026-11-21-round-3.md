# Round 3: cost per verified correct SECURITY_REVIEW answer (2026-11-21)

Mission 10 (Model Economy), route 1. Second full round under the pre-registered
[rule v2](../../bench/RULE-v2.md), same 46 cases as round 2. Payment moved to the node's escrow
rail ([amendment 4](../../bench/RULE-v2.md#amendments)), decided before any valid round-3 call.
Read this as a single day; the pooled report follows round 4.

## Setup

- **Run:** 2026-11-21, 1,564 calls.
  - 46 cases × 34 targets: the 33 miners that took a canonical request in that day's
    [audit](../../bench/out/round-3/audit.json) (all 12 from round 2 among them), plus the
    auto-routed ask.
  - One attempt each, at most 4 miners at a time.
- **Payment:** escrow on Ethereum Sepolia, test USDC, payer `0xA0C8…6C1C`. Each call signed
  locally; the receipt comes back in `X-PAYMENT-RESPONSE`.
- **Raw data:** [`bench/out/round-3/`](../../bench/out/round-3/): calls with receipts, the audit,
  the free baseline, the ledger before and after, and the scored output.
- **Reproduce:**
  ```
  python bench/score_v2.py bench/out/round-3
  python tests/test_reproduce.py
  ```

## Cost reconciliation

| Measure | Value |
|---|---:|
| Calls | 1,564 |
| Delivered (HTTP 200) | 591 |
| Escrow receipts | 591, all on delivered calls |
| Sum of receipts | 5,910,000 uUSDC ($5.91) |
| Ledger `charged + unbilled`, before → after | 20,000 → 5,930,000 |
| Ledger change | **5,910,000 uUSDC, equal to the receipts** |

The 20,000 before the round is the smoke test in amendment 4. `deposited` rose from 18 to 28 test
USDC during the round (a top-up); deposits don't enter `charged` or `unbilled`.

The 973 failed calls (759 × 500, 101 × 504, 81 × 503, 31 × 422, 1 client timeout) carry no receipt
and moved the ledger by nothing. On this rail, a buyer pays only for delivered answers.

## Findings

**1. One miner beats the free lookup; nobody else beats a constant answer.**

| Target | Package pairs (affected and latest both right) | Code pairs (vulnerable and fixed both right) |
|---|---:|---:|
| OSV lookup, free | 12 / 12 | 0 / 6 (abstains) |
| a1-preflight | 10 / 12 | 3 / 6 |
| telegraph-verity-intelligence | 0 / 12 | 2 / 6 |
| livecert | 2 / 12 | 0 / 6 |
| every other target | 0 / 12 | 0 / 6 |

(Twin pairs are exploratory, not pre-registered.)

- **a1-preflight** went from 27/36 to 31/36. The change is all on code:
  - Round 2: `Secure` on 10 of 12 snippets; 1 of 6 vulnerable snippets caught (path traversal).
  - Round 3: all 6 vulnerable snippets flagged `Insecure`, and 3 of 6 fixed snippets still flagged
    (path traversal, command injection, deserialization).
  - Its package answers are the same as round 2 apart from Maven (now 4/4). Go is still 2/4, from
    the shortened package name noted in round 2.
  - It now agrees with itself on all 8 format probes (round 2: 4 of 8).
- So its code behaviour flipped between rounds, from "says Secure" to "says Insecure". Round 4
  shows whether either is stable.

**2. The ranking still carries no information about accuracy.**
- τ = −0.18 over 27 ranked miners (round 2: +0.02 over 11).
- Ranks 1 and 2 scored 0/36. The most accurate miner is unranked.

**3. The default route again sends nearly everything to the rank 1 miner.**
- 43 of 46 routed calls went to `secrev-nvd-kw` (rank 1), 2 to a1-preflight, 1 to a deps.dev miner.
- Routed accuracy fell from 5/36 to 1/36. Rank 1 changed between rounds, and the route followed it.

**4. On escrow, failures are free, so cost per correct answer falls for weak miners.**
- telegraph-verity-intelligence: $0.058 per correct answer on x402 (round 2), $0.020 on escrow.
  Same 8 correct answers; it was billed for 16 deliveries instead of 46 calls.
- a1-preflight delivers on every call, so its cost barely moves ($0.017 → $0.015).
- Per amendment 4, cost is compared within a rail, not across. Round 2's finding that buyers pay
  for failures belongs to x402 exact and is not re-tested here.

**5. Most of the market still doesn't answer.**
- 591 of 1,564 calls delivered (38%), and 173 of those had a valid `verdict`.
- 9 miners returned nothing billable at all. The main errors are upstream 404s from the lookup
  service a miner wraps (for example "version not found"), and `unsupported_target` on code.

## Changes made during scoring

- **Scorer fix.** Scoring several rounds together kept each miner's rank from the first round,
  so round 3's τ would have used round 2's ranks. `score_v2.py` now takes the rank from each
  round's own records, with a regression test (`tests/test_reproduce.py`, `Round3`). Round 2's
  published numbers are unchanged.

## Limits

- One day, one wallet, testnet. Intervals are wide; read overlapping ones as ties.
- Code truth is by construction; a reviewer may defensibly flag extra concerns on a fixed snippet.
- 21 miners are new since round 2, so round-to-round comparisons cover only the 12 from round 2.
