## 4. Review the 86 pool pairs (this week, about 1–2 hours)

(Regenerated 2026-11-13 so each worse answer is about as long as the better one, as bounty #96 asks. Use the new `pool_review.csv`, not the 91-row one.)

The pool rules expect a human to check every uploaded row, and `tools/upload_pool.sh`
refuses unreviewed rows.

1. Open `pool_review.csv` (sent with the backup) in Excel, Google Sheets (**keep it in a
   private file**) or LibreOffice.
2. For each row:
   - Open `source_url` (the GitHub advisory). Check the affected package and the
     "Affected versions" / "Patched versions" boxes.
   - Read `prompt`, then `chosen`, then `rejected`. `flaw_note` says what's wrong with the
     rejected answer.
   - Write `approve` in `decision` if all three hold: (a) the chosen answer is correct
     about the version and advisory, (b) the rejected answer really is wrong for the reason
     given, (c) nothing in either answer is misleading.
   - Otherwise write `reject` and a few words in `notes`.
   - `label_checked_by` says OSV's own version lookup already confirmed the label, so you
     are mainly checking that the wording is fair and clear.
3. Save as CSV and upload it to this chat, saying the name to record as reviewer.
4. Claude runs `python tools/review_pool.py apply --reviewer "<name>"` and rebuilds the pool
   file with the full checks.

**Done when** Claude reports "approved N, rejected M, unreviewed 0".

## 8. Executor VM (only once step 9's bar is in sight)

Validators call a public HTTPS URL before they download the package. It must run the
**exact** registered package on the real foundation.

1. Rent a Linux VM with a public IPv4, **≥ 5 GB RAM** and ports 80/443 open (any VPS
   provider; Ubuntu 24.04).
2. Claude exports the final package once and commits it to `adapters/SECURITY_REVIEW.safetensors`
   (+ `.manifest.json`). Exports aren't byte-identical, so these committed bytes are the
   ones to register.
3. On the VM:
   ```bash
   sudo git clone https://github.com/Ritapossible/AdversarialEval /opt/adversarialeval
   cd /opt/adversarialeval
   sudo EXEC_HOST=<your-ip-with-dashes>.sslip.io bash deploy/setup_vm.sh
   ```
4. Tell Claude the URL. Claude runs `bash deploy/healthcheck.sh https://<host>/` from the
   cloud session. That is the node's own client with the private-address guard **on**, exactly as a
   validator calls it.

**Done when** the health check prints `identity echoed` and the WASM-vs-PyTorch agreement holds.

## 9. Register (only if the independent test accuracy is about 80% or more)

The rule exists because the node's first check uses only 15 pairs: at 75% true accuracy it
passes only 69% of the time, and at 80% about 84% (`MEMORY.md` → Decisions 11-11).

1. Claude scores the candidate on `data/test/` and reports accuracy with its confidence interval.
   Go only if it's about 80% or more and the lower bound is above 70%.
2. Host the package at an immutable URL (`https://raw.githubusercontent.com/Ritapossible/AdversarialEval/<COMMIT_SHA>/adapters/SECURITY_REVIEW.safetensors`)
   and check that `curl -sL <url> | sha256sum` matches the manifest.
3. Follow `docs/RUNBOOK.md` §8: approve MACHINA, **dry-run** `registerWasm` with `cast call`
   (free), then `cast send` it. Use the keccak256 from the manifest, intent
   `SECURITY_REVIEW`, the fee address, and the executor URL from step 8.
4. Keep the VM running. Track `curl -s $NODE/api/wasm/<registrationId>` (about 1.5 h) and
   paste the result to Claude for `eval/reports/`.
